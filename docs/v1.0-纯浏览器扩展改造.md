# v1.0 纯浏览器扩展改造方案

日期：2026-11-09。本轮把项目主体从「Python 本地服务 + 注入脚本」切换为**纯浏览器扩展**，目标是解决三件事：

1. 不再每次重新录入/确认资料；
2. 网申页字段能正确识别并填入；
3. 同一个网站之前失败过的字段，下次能直接命中。

旧实现（Python 本地服务 + 注入脚本）已在仓库精简时移除，仅保留在本地 git 历史中；用户已存资料（`profile.json`）未被修改。

## 1. 为什么换架构

旧链路的硬伤不在某个字段规则，而在部署链路：

```
招聘页 → 注入脚本 → 扩展后台 → Native Messaging 启动桥 → 本地 Python 服务 → profile.json
```

任何一环没启动（服务未运行、扩展重载、版本不一致、令牌失效），扫描和填写全部失败；用户侧表现为「又要重新输一遍」「识别不出来」「上次填过的这次还失败」。本轮实测：本地 8765 服务并未运行，扩展因此无法工作。

参考项目：

- [aurostars/Job-Application-Helper](https://github.com/aurostars/Job-Application-Helper)（MIT）：纯扩展、资料在 `chrome.storage.local`、字段识别 + 快速填充；
- [Yezi2002/NetApply](https://github.com/Yezi2002/NetApply)（MIT，基于前者改造）：字段注册表 + 分层匹配器 + 写前双重检查/写后回读 + 别名覆盖。

本轮以 NetApply 源码为基线（vendored 到 `extension-src/`），在其上做本项目需要的改造。

## 2. 目标架构

```
招聘页 ← content.js（扫描/匹配/填写/回读）
   ↕ chrome.runtime 消息
background.js（活动简历、别名学习持久化、备份/同步、AI 配置存储）
   ↕ chrome.storage.local
popup（快速填充、本页字段对照、记住一次） / options（资料、导入迁移、备份）
```

- **无本地服务、无 Native Messaging、无端口/令牌/版本握手**：安装后即可用；
- 资料只存在浏览器本机，字段识别与填写全部本地完成；
- 不使用云端 AI 生成答案，也不把已保存资料发送给模型（设置页保留配置入口，但标注未启用）。

## 3. 字段识别

沿用 NetApply 设计（详见 `extension-src/docs/DESIGN.md`）：

1. 结构化证据：`visibleLabel / placeholder / name / id / autocomplete / moduleContext / rowContext / inputType / controlKind` 分开保存，不做「大字符串裸 includes」；
2. 分层匹配：永久禁止字段 → 用户自定义别名 → 系统标准名/别名 → 字段专属上下文规则 → 安全内部标识符 → 不确定跳过；
3. 模块边界：教育/工作/项目/奖项上下文只用于限定作用域，不能被单独用来决定字段；
4. 写前检查：已有内容绝不覆盖；写后回读验证，失败不重试乱写；
5. 敏感字段黑名单：内推码、验证码、密码等永久禁止自动填写。

本轮增强（见 `diagnostics/coverage/` 报告与 `docs/v1.0-验证记录.md`）：

- 用旧工具保存的 922 条**真实页面字段**（20 个申请页）做离线识别诊断，按站点统计未命中字段；
- 据此扩充注册表别名/上下文规则，重点站点：hotjob、zhiye、Moka、智联、51job、国网、北森；
- 新增「本页字段对照」：填充后列出未识别字段，用户选择对应资料字段即保存为当前简历的永久别名，下次同名字段直接命中（解决「上次填过这次还失败」）。

## 4. 资料模型与一次性迁移

新模型（`extension-src/src/shared/types.ts`）：个人信息、教育经历、实习/工作经历、项目、奖项、证书、技能、自定义信息、自定义模块（家庭、语言、论文、科研等预设），外加 `fieldAliasOverrides`。

迁移入口：设置页 →「数据与同步」→「从旧版校招助手导入（profile.json）」。

- 读取旧 `profile.json`（默认 `%LOCALAPPDATA%\CampusFormAgent\profile.json`），纯本地解析，不联网；
- facts 27 项 → 个人信息/自定义字段；
- 教育经历按学校+学历+起止时间去重（旧数据存在 8 条重复扫描记录）；
- 项目/证书/家庭/语言/论文/实习/获奖分别映射；
- 旧字段映射（status=ready）的 label→canonicalKey 转为新扩展别名，迁移「此前已经认得」的字段；
- 展示条数摘要（不展示个人值）→ 二次确认后覆盖当前活动简历。

## 5. 填写安全边界（不因换架构而放松）

- 只填空白项，不覆盖页面已有内容；
- 不勾选协议、不点击提交、不上传附件；
- 高敏感字段按黑名单/敏感标记处理；
- 页面值写后回读，失败只报告，不反复写；
- 复杂级联、封闭 Shadow DOM、不可访问 iframe、需新增经历卡片等仍可能需人工处理。

## 6. 构建与加载

```powershell
# 首次
cd extension-src
npm ci --ignore-scripts --no-audit --no-fund

# 构建 + 校验 + 同步到可加载目录 extension/
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build_extension.ps1
```

加载：Edge/Chrome 扩展管理页 → 开发人员模式 → 加载解压缩的扩展 → 选择仓库根 `extension/`。

> 说明：`npm ci` 需要 `--ignore-scripts`，因为上游 devDependency `canvas` 会在安装时尝试从 nodejs.org 下载预编译二进制，本机网络策略会拦截；构建与运行不依赖该原生模块。

## 7. 验证分类（本轮）

| 类别 | 内容 |

| 代码修改 | 扩展源码改造：迁移、学习、识别规则、品牌 |
| 语法/类型检查 | `npm run build`（tsc + vite）、`node --check dist/content.js` |
| 后端映射诊断 | 离线匹配 harness 对真实字段目录的覆盖率报告 |
| 已部署扩展端到端 | **需用户在本机 Edge 加载扩展后验证**；本轮不声称已完成 |
