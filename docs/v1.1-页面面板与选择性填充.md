# v1.1 页面内悬浮面板与选择性填充

日期：2026-11-10。用户反馈两个问题：

1. **只能全量填充**：有时只想补几个字段，不想整页都填；
2. **点填充后状态/选择丢失**，没法边看页面边确认保存。

v1.1 把「字段选择 → 填充 → 核对 → 撤销」从弹窗搬到**网页内悬浮面板**，并默认关闭可能触发表单提交的自动点击。

## 1. 交互变化

- **工具栏图标**：点击打开/关闭页面内悬浮面板（不再默认弹出 popup）；面板右上角「更多」可在新标签打开原弹窗（投递记录、多简历、本页字段对照等仍在弹窗中）。
- **面板**：可拖动、折叠、Esc/× 关闭，位置与折叠状态记在本机；点网页不会关闭面板。
- **字段列表**：按模块分组（基本信息 / 教育经历 / 实习经历 / 项目经历 / 奖项 / 其它），每行显示：
  - 复选框（默认勾选「空白 + 有可填资料 + 可写」的字段）
  - 字段标题、当前状态（空白 / 已有内容 / 禁止 / 未识别）
  - 将填入的值（与真实填写同一套取值逻辑，预览值 = 实际写入值）
  - 命中的资料字段名、类型、是否在 iframe 内
  - 敏感字段（身份证/手机/邮箱/微信/出生日期等）默认 `••••` 遮罩，行内「显示」临时查看
- **选择方式**：逐字段勾选、模块级三态全选、全选空白、全不选。
- **填充**：只写入勾选字段；写前空白检查、写后回读验证；已有内容绝不覆盖。
- **结果与撤销**：每行显示成功/跳过/失败，底部统计；「撤销本次填充」只恢复「当前值仍等于本次写入值」的字段，用户手改过、节点已脱离、自定义下拉无法安全恢复的跳过并报告。
- **未识别字段**：面板底部折叠区列出，可到「更多 → 弹窗 → 本页字段对照」映射一次。

## 2. 防刷新与安全默认值

代码中原本没有任何 `location.reload`，但旧流程会在填充前点击页面上的「添加」按钮来补齐经历行。若站点按钮是 `<form>` 内默认 `submit`，点击就可能触发页面提交/刷新，导致“填完就刷新、没法保存”。

v1.1 处理：

- 默认 **不点「添加」**、不主动勾选「没有实习经历」（`allowAutoAddRows=false`，面板可显式开启）；
- 所有扩展主动点击（添加按钮、自定义下拉选项等）走 `clickSafely`：在捕获阶段对**该次点击**调用 `preventDefault`（阻止默认提交），不修改页面 `type` 属性、不阻止站点自身的 onClick，点击后立即移除监听；
- 填充前后记录 `location.href`，发生变化时面板/提示显示「检测到页面跳转/刷新，本次填充可能被站点打断」；
- 扩展绝不主动 reload/submit/勾选协议/上传附件。

## 4. 边界与未验证项

- 面板的 Shadow DOM 渲染、拖动、Esc、持久化与真实站点字段识别**尚未在真实招聘页验证**；隔离浏览器冒烟只能证明扩展加载与扩展页运行。
- 多帧页面按 `frame-<frameId>:<localId>` 路由；填充过程中 iframe 卸载会逐字段报 not-found。
- 撤销不支持自定义下拉框的安全恢复；单次填充失败只重试一轮（弹窗快速填充仍有两轮重新检测补填）。
- 站点自身 JS 触发的提交/刷新，扩展无法阻止，只能检测并告警。
- 面板填入的值仍需用户人工核对；扩展不提交、不勾选协议、不上传附件。
